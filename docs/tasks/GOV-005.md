Given：

- `TenantContext、trace_id 和 Idempotency-Key 可用`

When：

补充场景：

- Given 基线 Policy 卡，When 读取，Then 必须有唯一 `policy_key/policy_version`、owner、reviewer、至少一个证据引用、`effective_at` 和 `review_due_at`。
- Given Architecture MVP，When 生成 synthetic/dev 快照，Then `synthetic_only=true`，只允许 `manual_export`/`simulation`，`account_policy_version=null`，不得出现真实 Token、账号或平台 URL。
- Given `review_due_at` 已到期，When 进行 Policy Gate 前检查，Then 快照不得继续授权新的副作用任务，必须转人工并创建新版本。
- Given 相同 `policy_key/policy_version` 或相同快照哈希重复写入，When 执行迁移，Then 保留第一次事实并拒绝第二个版本/快照。
- Given 政策证据 URI 缺失、owner 未知或 reviewer 为空，When 校验卡片，Then 返回确定性校验错误且不创建快照。

## 实现规格

1. 创建 `policy-card.schema.json`，将政策卡模板加入 `governance.schema.json` union；保留既有 `PolicySnapshot` 契约作为快照输出。
2. 创建 `policy-card-baseline-v1.yaml`，引用 GOV-001/002/004 和本任务测试作为证据；规则明确账号未知、过期和 unknown 外部结果的人工/阻断行为。
3. 创建 `policy-snapshot-synthetic-v1.yaml`，只描述无账号 synthetic/dev 运行上下文；不得保存 Token、个人信息或真实平台地址。
4. 创建版本化 `policy_versions` 与 `policy_snapshots` 迁移；主键和快照哈希保证幂等，迁移重复执行不得删除历史。
5. 契约测试必须检查字段完整性、证据引用、到期边界、账号后置边界和迁移重复执行。
