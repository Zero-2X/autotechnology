## 实现规格

1. 创建 `docs/governance/raci-v1.yaml`，使用稳定的角色别名，不写入个人姓名、邮箱、手机号、Token 或平台凭证。
2. 固定内部角色：治理、产品、选题、研究、版权、内容、QA、Policy、审批、平台运营、安全事故、数据保护、审计和值班工程师。
3. 为选题、来源版权、知识与 Canonical、生产本地化、QA/Policy、人工审批、分发、事故、删除保留和反馈指标建立 RACI 矩阵；每项只能有一个 accountable 角色。
4. 为 R0–R4 定义主要负责人、替补角色、响应 SLA 和升级触发条件。
5. 明确审计独立性：审计人不得审批自己创建的内容，不能成为同一发布动作的唯一执行人与审批人。
6. 使用 `raci-policy.schema.json` 校验配置，并通过 `raci_policies` 版本化迁移保存策略。

## 补充场景

- 重复执行同一 `policy_key/policy_version` 时不创建第二份 RACI 策略。
- 删除 accountable 角色、增加第二个 accountable 角色或引用未知角色时必须拒绝。
- R0/R1 事故联系人缺失、无替补或 SLA 非正数时必须拒绝。
- 任何角色绑定真实人员的动作必须交给后续 IAM 任务，GOV-003 不保存个人身份数据。

## 回滚

- 使用上一兼容的 `policy_version` 回滚，不删除历史 RACI、审计和事故证据。
- 角色职责变化必须创建新版本，并重新执行审批权限、发布权限和事故演练检查。
