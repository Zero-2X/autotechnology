## 权限、幂等、失败和审计

- 风险策略只使用 `raci-role-map@1` 的逻辑角色，不写个人姓名、邮箱、手机号或凭证。
- 相同 `policy_key/policy_version` 只能存在一份；同键不同内容必须创建新版本，不能覆盖。
- 多个风险发现同时存在时取最高风险等级；无法确定的外部结果最低按 `R2` 处理。
- 风险降级必须创建新的版本化评估，引用原评估和证据；`R3/R4` 禁止自动降级或自动恢复。
- 后续写用例必须使用 `org_id`、`trace_id`、`Idempotency-Key` 和 `expected_version/If-Match`，并保持业务事实、AuditLog 和 Outbox 事务一致。

## 实现规格

1. 创建 `docs/governance/risk-policy-v1.yaml`，固定风险顺序为 `R0 < R1 < R2 < R3 < R4`，`R0` 表示最低风险，`R4` 表示最高风险；同一对象命中多个触发条件时取最高等级。
2. 风险维度至少覆盖 `content`、`factuality`、`rights`、`account`、`privacy`、`security`、`region_compliance`、`platform` 和 `runtime`。
3. 每个等级必须定义含义、结构化触发条件、允许自动化、阻断动作、人工升级模式、最低审批人数、响应 SLA、主要/替补角色、Kill Switch 要求、恢复要求和回滚规则。
4. `R0` 仅允许低风险、可逆的编辑处理；`R1` 允许有上限的自动修复或内部临时错误重试；`R2` 必须暂停相关副作用并进入人工处理；`R3` 必须双人审批并触发范围化 Kill Switch；`R4` 必须立即隔离、Kill Switch 和事故响应。
5. `R2` 至少覆盖事实冲突、版权/权利不确定、疑似 PII、持续性运行故障和 unknown 外部结果；unknown 禁止自动重发。
6. `R3` 至少覆盖高风险内容、已拒绝权利仍请求分发、区域/合规冲突、Policy 绕过和恶意提示注入；`R4` 至少覆盖凭证泄露、未授权真实发布、确认的重大隐私泄露和生产安全失陷。
7. 无账号的 `architecture_mvp` 只允许 `manual_export` 和 `simulation`；任何读取、生成、保存真实凭证或调用真实平台 API 的请求均视为严重治理违规并至少进入 `R4`。
8. 将 `raci-v1.yaml` 的联系人顺序校正为相同的递增风险语义，且每个等级的负责人、替补和 SLA 与风险策略一致。
9. 使用 `risk-policy.schema.json` 校验机器策略，并将该 Schema 加入 `governance.schema.json` union；迁移创建版本化 `risk_policies` 表，不保存真实账号或凭证。
10. 本任务不新增 OpenAPI 操作或领域事件；后续分类、Policy、审批和 Kill Switch 任务必须引用本策略版本。

## 补充场景

- Given 仅发现格式、元数据或可逆草稿问题，When 分类，Then 为 `R0`，不得因此触发 Kill Switch。
- Given 出现普通质量问题或可恢复内部临时错误，When 分类，Then 为 `R1`，只允许有上限、无外部副作用的自动修复或重试。
- Given 事实冲突、权利不确定、疑似 PII 或 unknown 外部结果，When 分类，Then 最低为 `R2`，停止相关副作用并创建人工核查；unknown 禁止自动重发。
- Given 高风险内容、区域/合规冲突、Policy 绕过或提示注入，When 分类，Then 最低为 `R3`，需要两名不同审批人并启用范围化 Kill Switch。
- Given 凭证泄露、未授权真实发布、确认的重大隐私泄露或生产安全失陷，When 分类，Then 为 `R4`，立即 Kill Switch、隔离和事故响应，禁止自动恢复。
- Given `architecture_mvp`，When 请求读取真实 Token 或调用真实平台 API，Then 至少分类为 `R4` 并阻断请求，不产生真实外部副作用。
- Given 相同策略迁移已执行，When 再次执行迁移，Then 不删除历史数据且不创建重复表；相同主键重复插入必须被拒绝。
