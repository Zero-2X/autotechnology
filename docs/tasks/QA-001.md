## 实现规格

- `QAService.check_variant` 只读取同租户的 VariantVersion、CanonicalVersion、Claim 和 Evidence 投影，生成符合 `qa-report.schema.json` 的报告；不更新任何业务事实，不调用网络、模型或平台。
- Claim/Evidence 检查验证租户、Claim 状态/新鲜度/有效期、Evidence 状态/有效期/quote/source snapshot、Claim 到 Evidence 的关联和 Variant source map 的 Claim 映射。
- 时效、数字、引用、代码和链接检查均为确定性规则：Canonical 与 Variant 的数字、代码片段和 URL 计数必须一致；过期或撤回事实生成失败 finding；缺少引用、quote 或 locator 生成失败 finding。
- 术语检查通过可替换 `TerminologyPort` 注入，Port 只返回结构化问题；没有 Port 时不伪造术语结论。所有 finding 包含 code、severity、path、message、observed 和 expected，并按稳定键排序。
- 同租户同幂等键与输入重放原报告，参数不同返回 `IDEMPOTENCY_KEY_REUSED`；报告保留 rule_version、created_at，内存审计记录 trace、actor、输入/输出哈希。

补充场景：

- Given 已验证 Claim、有效 Evidence、完整引用且内容保护通过，When 检查，Then 返回 `passed`。
- Given Claim 过期/撤回、Evidence 缺失或 Variant 未映射 Claim，When 检查，Then 返回 `failed` 并定位对象。
- Given 数字、代码或链接在 Variant 中丢失/新增，When 检查，Then 返回对应 finding，不自动修复文本。
- Given 术语 Port 返回问题，When 检查，Then 将其纳入 `needs_review` 或 `failed` 报告，不调用模型重写。
- Given 其他租户 Claim/Evidence/Variant，When 检查，Then 返回 `TENANT_SCOPE_VIOLATION`，不泄漏对象内容。
