## 实现规格

1. 创建 `docs/governance/release-levels-v1.yaml`，固定顺序为 `architecture_mvp`、`distribution_pilot`、`scale`。
2. `architecture_mvp` 必须无真实账号，只允许 `manual_export` 和 `simulation`；不得使用真实 OAuth、Token、平台 HTTP、自动客服发送或真实指标。
3. `distribution_pilot` 必须要求一个真实主体、一个真实账号和一个官方平台，先 `draft_only` 后低频受控发布；必须使用新的 AccountConnection、TargetVersion、PolicySnapshot 和 PublicationIntent。
4. `scale` 只有在试点指标、事故演练、成本、SLO、RPO/RTO 和人工负载达标后才可启用；架构拆分不能只按账号数量决定。
5. 每个级别必须定义 entry_gates、exit_gates、rollback_rule、allowed_capabilities 和 forbidden_capabilities；配置版本不可原地覆盖。
6. 使用 `release-levels.schema.json` 校验配置，并通过 `release_level_policies` 迁移保存版本化策略。
