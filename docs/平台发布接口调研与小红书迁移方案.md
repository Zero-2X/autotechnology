# 平台发布接口调研与小红书迁移方案

调研日期：2026-09-21。状态：首轮官方资料核查完成；私有参考仓库尚不可访问，平台真实联调尚未开始。

## 结论

“我的账号没有获批接口权限”和“平台没有发布 API”是两回事。工作流应按平台、账号和动作选择接入方式，不能把所有平台统一改成网页自动化。发布、读取评论、回复评论、私信、数据统计分别核验，不能共享一个“已授权”布尔值。

用户确认现有账号没有接口权限。小红书首个试点可以转向浏览器发布路线的实现评估，不再把申请官方 OAuth 作为所有路线的共同前置条件。但此结论不代表浏览器适配器已经实现，也不代表已经核验账号能够自动发帖。

## 迁移设计（待源码核查后实现）

继续使用现有 Planner/Research/Transform/QA 生成与审核内容，在 distribution 边界增加可选浏览器适配器；不把 LLM 节点变成直接点击发布的执行器。

建议链路：选题 → 模型生成 → 素材与事实检查 → 内容版本 → 审核 → 选择账号接入方式 → 发布执行 → 平台结果回查 → 保存回执。

每个账号分别记录发布、评论读取、评论回复、私信读取、私信回复能力。官方 API 模式检查获批权限；浏览器模式检查独立登录态和目标账号身份；两者都没有时导出给人工。浏览器能力与 API Scope 分开保存，不伪造 OAuth 授权记录来通过现有检查。

浏览器运行器应在用户本机或独立受控服务上执行。已经上线的 Sites 静态页面不能直接继承电脑上的小红书登录态，也没有持久浏览器运行环境；网页需通过受认证的后端提交任务，不能把登录 Cookie 放入前端 localStorage。

发布任务需要持久化的幂等记录，绑定账号、内容版本和动作。提交后超时记录为“结果未知”，先回查再决定后续动作；不得直接重试点击发布。页面结构变化、验证码、异常提示或账号身份不符时暂停当前任务。

客服独立运行：取得消息 → 去重 → 分类 → 生成草稿 → 根据已验证的规则发送或转人工 → 保存发送结果。先验证评论，再独立验证私信，不因发稿成功就开放全部客服。

## 模型代理实现与边界

已新增 `integrations/langchain/responses.py`，使用现有 httpx 与 jsonschema 依赖。通过现有 ModelPort/ChatModelAdapter 接口使用，无需引入另一套模型 SDK。

- 供应商：`zpproxy`。
- 地址：`https://webaiproxy.top/v1/responses`。
- 凭据变量：`OPENAI_API_KEY`，只在服务端读取。
- 选择开关：`MODEL_PROVIDER=zpproxy`，用于明确当前密钥的目标服务。
- 模型：必须提供代理认可的精确 ID，不把 `5.6sol` 等简称自动转换成猜测名称。
- 使用非流式 Responses，请求 `store=false`，解析消息中的 `output_text` 和 token usage；结构化输出在本地再次校验。
- 不跟随重定向、不自动重试、不在错误消息中输出服务端正文或密钥。
- 该实现不管理 ChatGPT 账号池，不转换登录 Cookie，也没有验证代理支持全部模型的说法。`store=false` 是请求参数，不能证明第三方实际零留存。
- 已接入本地网页的内容草稿和低风险客服回复按钮；服务端按配置优先调用模型，失败时自动回退本地模板。
- 当前价格未知；兼容 ModelCall 的默认费用字段不应被理解为实际免费，正式预算计费需补充代理价格。

参考协议：[OpenAI Responses 创建接口](https://developers.openai.com/api/reference/cli/resources/responses/methods/create)。第三方兼容性仍需实测。

参考仓库已从本地目录读取。它是 Apache-2.0 项目，使用 Playwright 与独立浏览器上下文保存会话；已实现小红书创作者中心登录、图片上传、标题和正文填写、发布按钮点击。其当前发布逻辑点击按钮后即返回成功，没有核验笔记 ID、链接或发布状态；本项目不会直接复制这个成功判定。源码中没有找到完整的评论或私信自动回复实现。

本项目已加入 `adapters/xiaohongshu/browser.py` 的受控浏览器适配器：检查 HTTPS 创作者中心、账号绑定、唯一上传控件和编辑器回读；可在明确确认后点击发布，但仍要求重新查询平台结果，不把 Cookie 写入前端，也不声称已发布。它已经接入本地 API 和发布中心，真实账号仍需通过账号持有人确认身份和发布结果。

当前工作流已增加统一路由：每个动作先检查该账号是否有明确批准的官方 API 能力；有则使用 `authorized_api`，没有则检查独立登录浏览器会话并使用 `browser_automation`，两者都不满足时导出 `manual_export`。小红书的发布、收件箱、评论回复和私信回复默认没有 API 动作，优先走浏览器适配器；其他平台只有在账号能力快照明确授权后才走 API。

当前本机使用 `MODEL_ID`（未设置时默认为 `gpt-5.6-sol`）选择模型。已验证 Responses 请求可以返回结构化内容；代理偶发超时或拒绝时会返回本地模板并记录 `fallback_reason`，不会阻塞后台。
