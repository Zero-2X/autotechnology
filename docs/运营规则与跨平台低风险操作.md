# 运营规则与跨平台低风险操作

更新：2026-09-24

后台现在把所有平台放在同一套操作规则下。规则只控制本机工作流，不保存账号密码、Cookie、验证码或 API 密钥，也不会替代平台自己的审核和风控。

## 目前可以直接使用的流程

1. 在“账号矩阵”登记平台、账号名称、负责人和内容栏目。登录凭据只在平台官方页面完成；小红书使用独立的本机登录窗口。
2. 在“内容工作室”生成或填写草稿，上传配图，完成审批。图片会在浏览器本地压缩保存，正文和配图可以随时导出。
3. 在“发布中心”选择账号。已经接入官方 API 的平台将来可以走正式接口；当前未获授权的平台会导出内容包并打开官方工作台。
4. 在官方页面核对账号、标题、正文、图片、话题和平台提示后，由运营人员完成发布；回到后台登记平台链接或对象编号。
5. 在“客服收件箱”从官方后台复制评论或私信，选择账号、渠道和风险，生成回复草稿，复制回官方页面发送，再登记结果。高风险、投诉、版权、售后和不确定消息继续转人工。

这套流程可以同时管理小红书、抖音、TikTok、YouTube、Instagram、LinkedIn 等账号。平台没有正式接口时，后台仍然能管理内容、素材、账号、消息草稿和发布记录，但不会假装已经接通官方消息接口。

## 运营规则卡片

“连接与设置”中新增“运营规则与紧急停止”：

- 默认每日发布上限为 3 条、每周上限为 15 条，可按试点情况调整。
- 可以停用全部发布和回复入口。紧急停止只阻断新的发布准备、发布和回复动作，不删除已有草稿或消息。
- 规则按账号标识统计。后台会同时识别账号 ID 和账号名称，无法解析时间的旧记录按当前窗口保守计数。
- 统计时区默认为 `Asia/Shanghai`，每日和每周边界按这个时区计算。
- 规则写入本机 `.local/operations-policy.json`，不进入 Git；换机器时应重新检查。
- 网页自动点击发布和网页自动回复的两个底层开关默认都是关闭的；普通设置页不能直接打开它们。即使误调用旧入口，API 也会先拒绝。

当达到限额或启用紧急停止时，小红书“准备草稿”入口会在 API 层返回阻止结果，浏览器窗口不会被启动。客服人工导入仍然可用，因为它不会向平台发出动作。

## 试点与排期

后台的“试点与排期”页面现在可以建立一份本地试点计划。计划包含：

- 试点账号、负责人和替补负责人；
- 开始/结束时间、每日和每周发布上限；
- 一行一个的停发条件，例如版权投诉、异常登录提示或负责人无法复核；
- 每条内容的目标账号、计划时间和内容编号；
- 试点开始、停止、完成和复盘记录。

保存试点只会写入本机 `.local/pilot-runs.json`，不会打开平台页面，也不会发送发布或客服动作。建议先建立一个账号、排一到两周的内容，完成人工确认后再逐步增加账号。试点停止后不能继续添加排期，避免误把旧计划当成正在运行的计划。

这套排期是运营控制台的本地计划层，尚未替代任何平台的官方排程接口。只有在平台账号授权、接口 Scope、结果回查和撤销机制都通过验证后，才应把某个平台切换到正式 API。

## 降低账号风险的默认策略

- 不设置定时刷新，不在后台持续扫描评论或私信页面。
- 不把“登录会话已连接”当成发布或客服权限。
- 未经平台批准的动作统一降级为人工导出；浏览器填稿也停在最终确认前。
- 每次发布先审批，再由运营人员在官方页面核对；平台显示失败但结果不确定时先回查，不重复点击。
- 回复先生成草稿。低风险内容也由运营人员复制到官方页面发送；高风险内容必须转人工。
- 先用一个账号、低频率运行两到四周，再根据失败、投诉、重复发布和平台提示决定是否增加账号。

## 何时可以升级为正式 API

只有同时具备平台官方应用、明确的账号授权 Scope、回调或消息权限、调用限额、撤销机制、健康检查和发布结果回查时，才把对应动作切换为 API。每个平台、每个账号、每种动作都要单独验证；拿到一个平台的权限不会自动覆盖其他平台。

在这些条件满足前，当前后台已经可以作为统一的内容和客服操作台使用。它能减少重复复制和漏记，但不能保证平台风控为零，也不会绕过平台规则。
