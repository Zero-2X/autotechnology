管理层结论

项目主体已经搭好，可以开始真实业务的人工辅助试运行；要实现多账号自动发布，还需要把真实平台、生产凭据和运营试点接上。

进入受控试点前
目前可交付 “AI 生成 + 质量治理 + 人工审批 + 人工导出发布”闭环

系统已经能组织选题、内容生成、来源与版权检查、质量检查、审批、版本、审计和导出，并能用真实 LangGraph 编排这些步骤。文本模型已接入 zpproxy Responses；内容草稿与低风险客服草稿完成过真实请求验证，单次生成通常需 45–50 秒，后台会标出是否实际使用模型；Seedance 视频生成尚未接入。小红书专用浏览器账号已重新扫码，后台当前显示连接正常。图文草稿可排队填入；自动进入客服消息区尚未匹配当前页面入口。本轮补上“手动进入消息页后扫描当前页”的路径，并将真实消息默认置为待人工判定；读取、回复和回查仍需账号本人实际验收。

尚未开放

真实平台一键自动发布

小红书不依赖未获批的官方 API，采用账号持有人登录后的浏览器自动化；其它平台仍需各自的官方权限或对应浏览器适配器。Secret Vault、生产存储、平台回查和 2–4 周 Pilot 尚未完成，现阶段不能把点击动作直接描述成平台已发布。

这个项目解决什么问题

把跨境技术内容从“人工零散生产”变成可复制、可审计、可扩展的流水线。

提高内容产能

同一个选题可以生成不同语言、渠道和账号版本，减少重复写作和排版。

  • 主题与受众结构化
  • 中文/英文内容变体
  • 多账号内容包输出

降低品牌与合规风险

内容发布前经过来源、版权、政策、质量和人工审批，任何修改都可追溯。

  • 来源和证据引用
  • 审批人与执行人分离
  • Kill Switch 与回滚边界

形成可持续增长闭环

发布结果、互动和成本可以回流成改进建议，后续支持选题和内容优化。

  • 内容效果观察
  • 成本与质量指标
  • 反馈和推荐机制

一条内容如何流转

每一步都有明确输入、责任人和审计证据，避免 AI 内容未经验证就直接发布。

1选题与目标

确定受众、语言、账号和内容栏目。

2研究与生成

基于来源和证据生成可编辑草稿。

3质量与合规

检查事实、版权、政策、格式和风险。

4人工审批

审核内容、目标账号、媒体和发布时间。

5导出或发布

小红书可用浏览器准备草稿并在人工确认后尝试提交；其它平台按已批准的 API 能力或人工导出处理。

6回查与反馈

登记平台对象、指标、投诉和改进建议。

如果现在有几个真实账号

可以开始账号矩阵的准备和人工辅助运营，但不建议立即开启全自动多账号发布。

建议先单账号

现在可以启动

  • 建立账号矩阵、责任人、语言、栏目和发布上限
  • 生成不同账号的内容草稿和语言变体
  • 完成质量检查与人工审批
  • 人工导出并登录平台发布
  • 登记最终 URL、平台对象 ID 和效果数据

暂时不能直接承诺

  • 一键连接所有真实账号
  • 自动保存或轮换真实 Token
  • 无需人工审批的自动发布
  • 自动拉取所有平台指标
  • 已经具备生产规模的账号矩阵
⚠
真实账号不是唯一条件

还需要官方开发者应用/Sandbox、批准 Scope、Secret Vault、托管数据库、私有对象存储、平台回查和运营授权。账号密码或 Token 不应通过聊天或代码仓库提供。

为什么可以认为主体研发质量可靠

项目不是靠演示页面判断完成，而是通过机器注册表、契约和可重复测试验证。

从现在到账号矩阵上线

后续工作的重点已经从“继续搭框架”转为“接真实平台、部署生产基础设施、跑小流量 Pilot”。

阶段 1｜主体平台和无账号闭环 — 已完成

内容、知识、媒体、质量、审批、人工分发、分析、反馈、支持和编排底座已完成。

阶段 2｜首个平台和首个账号 — 浏览器已连接

小红书账号持有人已在独立浏览器重新扫码；消息入口与发布回执仍需真实页面验收。其它平台再分别确认官方应用、Scope、回调和账号所有权。

阶段 3｜生产接入 — 待建设

接入 Vault、托管 PostgreSQL、对象存储、Worker、告警和一个官方平台适配器。

阶段 4｜Draft-only / Sandbox 验证 — 待执行

验证授权、草稿创建、幂等、回查、撤销、过期、权限变化和 Kill Switch。

阶段 5｜单账号 2–4 周 Pilot — 待执行

低频发布，持续记录质量、成本、平台健康、投诉、指标和人工工作量。

阶段 6｜Go/No-Go 与矩阵扩展 — 待决策

单账号稳定后再逐个增加账号；每个账号都有独立责任人、上限和回滚方式。

下一步需要老板支持的事项

只要这些业务和基础设施条件到位，研发就可以继续完成真实平台接入。

1. 指定首个平台和试点账号

从几个真实账号中选 1 个风险最低、授权最清晰的账号，指定账号负责人和替补。

2. 确认平台与法律授权

提供主体、授权联系人、官方开发者应用/Sandbox、批准 Scope、平台条款和撤销路径。

3. 批准生产基础设施

确认已接入模型服务的数据条款与费用预算，建设 Vault、托管 PostgreSQL、私有对象存储和告警渠道。

4. 批准 2–4 周受控 Pilot

确定日/周发布上限、人工审批、暂停条件、质量和成本指标，并接受先低频后扩张。
